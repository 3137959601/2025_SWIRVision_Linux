# SWIRVision Qt上位机

本工程是SWIR_400W FPGA的配套Qt上位机，用于2048×2048、16 bit短波红外图像接收、显示、保存、串口控制、周期遥测和算法调试。当前版本与`SWIR_400W3`的8字节下行命令、40字节上行长帧、双温区15套两点参数以及USB行协议配套使用。

主要功能包括：

- FX3多端点图像接收、三帧并行组装和OpenGL灰度显示。
- 原始数据流、16 bit图像及调试统计数据保存。
- FPGA两点、坏点、中值、镜像、直方图、线性拉伸、自动积分和中心ROI控制。
- 积分时间、COM电压、探测器增益、TEC目标温度、TEC使能及电源控制。
- 15套两点参数手动选择，并兼容“三温区5+5+5”和“双温区8+7”界面布局。
- 40字节遥测的连续解析、状态显示、校验错误统计和CSV记录。
- 软件直方图调节及线性拉伸亮暗场采集、K/B计算、微调和CSV导出。

## USB图像解析与多帧组装

### 数据格式

FPGA通过FX3发送2048×2048、16 bit图像。每一行是一个独立数据包：

- 行头：16字节。
- 像素载荷：2048×2=4096字节。
- 单行总长度：4112字节。
- `byte[0..3]`：固定行头`90 EB 00 00`，对应FPGA字`0x0000_EB90`。
- `byte[4..7]`：宽度和高度，当前均为2048。
- `byte[8..9]`：行号，范围1至2048。
- `byte[10..11]`：16 bit帧号，允许自然回绕。
- `byte[12..15]`：固定结束标记`FF FF 23 01`，对应FPGA字`0x0123_FFFF`。

解析器会同时校验魔数、宽高、行号范围和固定结束标记。不能只搜索
`90 EB 00 00`：16 bit图像载荷中可能自然出现相同四字节序列，若把像素中的伪魔数当作
行头，会跨过后续真实行包并表现为每帧固定缺少少量行。

解析入口位于`transfer_thread.cpp`。只有同一帧的2048行全部到齐后，才把完整图像复制到
`widget_image`共享缓冲并通知显示线程，禁止用上一帧残留行拼接不完整图像。

### “USB有速率但无图像”的原因

上位机同时使用多个USB接收线程。Windows异步请求的完成顺序不等于FPGA发送顺序，帧边界附近可能出现：

```text
帧N：行2041..2048
帧N+1：行29..若干行
帧N+1：行1..28（稍后到达）
```

旧实现只维护一个正在组装的帧。它一旦看到更大的帧号便立即清空上一帧，导致迟到行被永久丢弃；
之后每帧都可能缺少少量行，始终达不到2048行完整条件，界面因此没有图像，但USB速率仍然正常。

该问题在增加FPGA光纤并行输出并重新布局布线后更容易复现。光纤链路没有对USB施加反压，重新编译只是
改变了各USB端点和主机异步请求的相对完成时序，从而暴露了上位机原有的单帧缓存假设。

### 当前修复方案

`transfer_thread.cpp`现在最多同时维护3个按`frame_num`区分的帧槽：

1. 相邻帧交错到达时分别写入各自的像素缓冲和行接收位图。
2. 每行只计数一次，收到重复行时允许更新像素，但不重复增加行数。
3. 任一帧收齐2048行后才发布，并丢弃该帧及更旧的缓存。
4. 已发布帧的迟到数据直接拒绝，防止画面回退。
5. 仅保留最新帧及其前两个相邻帧，防止异常旧数据无限占用内存。
6. USB采集线程全部退出后再次启动时清空状态，兼容FPGA帧号重新从0开始。
7. 帧号比较使用16 bit模运算，兼容`65535 -> 0`回绕。

三帧缓存对2048×2048×16 bit图像最多占用约24 MiB，换取跨端点、跨帧乱序条件下的稳定组帧。

使用`datastream_20260806_191645.raw`验证时，共识别135661个有效行包。按帧号归类可恢复56个完整帧；
旧单帧策略在后半段因迟到行持续丢帧，三帧窗口能够发布全部56个完整帧。这说明该次无图像问题发生在
上位机组帧层，而不是FPGA没有输出图像载荷。

## 串口协议与遥测

### 下行命令

所有控制统一通过`UartProtocol::buildCommand()`生成固定8字节帧，避免主窗口和调试窗口分别手工计算校验：

```text
EA 01 CMD CTRL DATA_H DATA_L CHECKSUM 0A
```

`CHECKSUM`为`CMD + CTRL + DATA_H + DATA_L`的低8位。主窗口与“串口调试状态”窗口复用同一命令构造和串口线程；调试窗口把指令设置与状态回读放在同一界面，无需在两个窗口之间切换。

当前重点控制包括：

- 手动积分、COM电压、两点G/O/开关、坏点、中值、镜像和增益。
- 自动积分开关、中心ROI/全幅统计、15℃和40℃积分上下限、3000/5500亮度阈值。
- 15套两点区域选择，界面可切换“三温区5+5+5”和当前“双温区8+7”布局。
- TEC温度、TEC使能、TEC电源和自动温区控制。TEC界面按温度显示，发送时通过既有三次映射换算成DAC电压/码值。
- 直方图开关及上下平台滑条，默认下平台320、上平台3200；滑条带短延迟合并，避免拖动时连续发送过多命令。
- 线性拉伸开关和K/B档位、十字线、锐度、配置固化及两点固化。

FPGA未实现或已经废弃的单点校正、帧间滤波和重复“增强”控制不作为可用按钮，避免界面发送没有实际作用的命令。完整命令码以FPGA工程`readme.md`和`doc/uart_protocol_400w.md`为准。

### 40字节周期长帧

FPGA每100ms发送一帧固定40字节遥测，不再使用短帧。`SerialWorker`直接在`QByteArray`缓存中查找帧头，能够处理半包、粘包、前置脏数据、校验错误和错误帧后的重新同步。

上位机当前显示和记录的核心状态包括：

- 实际生效积分时间、13 bit像素均值和板温。
- ITEC、VTEC、TEC实际温度、TEC设定温度和COM设定值。
- 锐度、十字线坐标、K/B档位、手动区域、实际生效区域和温度组。
- 自动积分、中心ROI、自动温区、TEC/TEC电源、两点、坏点、中值、直方图、镜像、拉伸、锐度和增益状态。
- 版本日期、Flash初始化、配置固化完成和两点固化完成状态。

状态使用醒目的红/绿标记区分关闭与开启；Flash固化按钮发送后由Qt先恢复为“未完成”，只有收到FPGA后续长帧中的完成状态才重新显示完成。调试窗口可把每帧遥测及时间戳持续写入CSV，便于温控、自动积分和长期稳定性分析。

## 自动积分与两点区域

当前FPGA运行布局为两组15套表：

| 温度组 | 区域 | 两点表数量 | 自动积分档位 |
| --- | --- | ---: | ---: |
| 15℃ | `0..7` | 8 | 32，每4档对应一张表 |
| 40℃ | `8..14` | 7 | 28，每4档对应一张表 |

自动温区关闭时，用户可通过15个区域按钮手动选择；开启后，FPGA根据板温和回差自动选择温度组，并在组内依据自动积分档位选择两点表。界面同时显示手动区域、当前实际生效区域、温度组、实际积分时间和像素均值，不能只根据最后一次按键推测硬件状态。

当前默认积分范围为15℃组0.10至30.00ms、40℃组0.10至22.00ms，亮度增档/减档阈值为3000/5500。参数经串口修改后需执行“固化配置”才能在下次上电恢复。

## 图像处理与标定工具

### 硬件直方图

FPGA直方图采用上下平台阈值映射，Qt调试窗口提供上下两个滑条和数值框。上下平台是每个灰度桶的像素计数阈值，不是输入图像的灰度上下限；设置时必须满足`upper > lower`。硬件直方图参数可随配置固化到Flash。

### 软件直方图与线性拉伸

主界面保留软件直方图/平台调节，用于快速观察显示效果；它与FPGA端硬件直方图不是同一条处理链，因此相同数值不保证视觉效果完全一致。

“线性拉伸标定”窗口只做上位机软件统计，不切换两点区域或发送其他硬件控制。区域选择继续在串口调试窗口完成，标定窗口接收当前帧和遥测区域信息，完成以下工作：

1. 在指定区域采集多帧无光暗场和标准亮场。
2. 记录均值、帧间标准差、积分时间、温度和ROI信息。
3. 根据亮暗场与目标黑白电平计算基础K/B。
4. 在基础参数上调整K倍率和B加法偏移，实时观察软件拉伸效果。
5. 导出区域汇总CSV和逐帧样本CSV，供后续比较15套初始参数和确定FPGA量化范围。

输入图像由USB 16 bit字恢复为13 bit DN后参与统计；当前FPGA硬件线性拉伸仍以13 bit有效数据为基础，文档中的K/B不能直接当作16 bit满量程参数使用。

## 关键修改记录

- 串口协议收敛为共享构造器和共享解析器，修复重复编码、校验不一致及半包/粘包问题。
- 将指令设置与遥测状态合并到一个非模态调试窗口，重新组织相关算法按钮并禁用无硬件实现的功能。
- 增加15套两点区域按钮、双温区8+7兼容布局、当前区域高亮和自动温区状态显示。
- COM和TEC由原始码改为物理量设置与显示；修正十字线Y方向操作语义。
- 增加像素均值、实际自动积分时间、Flash完成状态以及全部算法状态的周期显示和CSV记录。
- 增加直方图上下平台滑条和串口控制，默认值与FPGA Flash配置一致。
- 增加独立的软件线性拉伸标定工具及可复现的数据导出。
- USB解析从单帧缓存改为三帧并行组装，修复重新布局布线后多端点行包跨帧乱序导致“USB有速率但无图像”的问题。

## 构建与验证

工程文件为`SWIRVision.pro`，使用Qt Creator打开。当前已使用Qt 6.10、MSVC2022 Release构建验证；OpenCV目录仍以本机`SWIRVision.pro`配置为准。

当前Linux/RK3588复现入口位于`scripts/linux/`：

1. Ubuntu使用`build_x86_64.sh`构建、`run_x11_software.sh`运行。
2. RK3588使用`build_rk3588_native.sh`构建、`run_rk3588_x11.sh`运行。
3. `generate_synthetic_raw.py`用于生成离线回放样例。
4. 串口连接实机后检查40字节帧刷新、校验错误和硬件回读状态。
5. USB连接实机后检查完整帧、丢行/丢帧、停止和重连。

已完成的自动测试源码和测试脚本于2026-09-11从当前工作树精简；验证记录仍保存在Git提交`3331952`及`docs/迁移执行日志.md`中，需要时可从Git历史恢复。
