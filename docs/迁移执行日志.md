# 400W Qt Linux/RK3588迁移执行日志

## 一、记录目的

本文档记录迁移过程中实际执行的查询、下载、安装、文件同步、源码修改、构建、测试和调试操作，服务于以下目标：

1. 任何结论都能追溯到实际命令和输出证据。
2. 环境损坏或虚拟机重装后，可以按记录重新搭建。
3. 区分“只读查询”“文件修改”“软件安装”“系统级变更”和“失败尝试”。
4. 便于后续复习Linux、Git、Qt构建、动态链接、USB和RK3588部署知识。

记录不得包含密码、私钥或其他敏感凭据。公钥指纹、软件版本和公开仓库地址可以记录。

## 二、单条记录格式

每项操作至少包含：

- 编号与日期；
- 目标环境；
- 操作类型；
- 执行原因；
- 关键命令；
- 输出与证据；
- 文件或系统变化；
- 结论与下一步。

其中“关键命令”必须记录实际执行过的命令，而不是只记录计划。若一次操作包含大量重复查询，可以保留能够复现结论的代表命令；失败命令也必须记录其退出状态和错误摘要。

任何失败操作还必须补齐以下字段：

1. **失败现象**：原始错误摘要、退出码、卡住阶段或缺失文件。
2. **根因判断**：区分直接触发条件和更深层原因。
3. **判断证据**：说明用哪些查询支持根因，并排除了哪些可能性。
4. **解决方法**：记录实际采用的修复命令或代码修改。
5. **方案理由**：解释为什么选择该方法，以及为何没有采用覆盖系统库、混装版本、忽略错误等替代方案。
6. **修复验证**：用版本、文件、返回码、重新构建或运行测试证明问题已经闭环；尚未验证时必须明确标记。

失败不是需要隐藏的过程。只有“错误—证据—根因—修复—复测”全部记录，日志才具有学习和复现价值。
